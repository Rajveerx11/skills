# Frontend Design

Build a real interface with a coherent point of view. Visual novelty never outranks usability, content truth, accessibility, or compatibility with the existing product.

## Route near matches

- Use this skill for implemented product UI: application pages, dashboards, authenticated surfaces, workflows, and reusable components.
- Use `build-premium-website` for complete marketing/company/campaign sites and conversion landing pages.
- Use `design-taste-frontend` for portfolios or visual-first anti-generic redesign direction.
- Use `impeccable` when the requested outcome is critique, audit, polish, adaptation, or focused improvement rather than new product UI implementation.
- Use `ui-ux-pro-max` for UX research, mobile/product-pattern guidance, palette/type-system selection, or guideline analysis without an implementation-first brief.

Choose one dominant skill. Combine only when the request contains separable implementation and review/research deliverables.

## Read the product

Inspect repository instructions, framework, routes, components, design tokens, assets, content, data shapes, tests, and Git status. Derive:

- user and job to be done;
- content hierarchy and primary action;
- brand cues already present;
- technical, accessibility, performance, and viewport constraints.

Ask only when a missing decision changes product behavior, brand identity, or irreversible scope. Infer ordinary UI details from the project.

## Direct the design

Explore two or three distinct internal directions, then commit to one. Name:

- concept and emotional tone;
- signature visual or interaction;
- typography roles and color logic;
- composition system and density;
- motion language and reduced-motion equivalent.

Choose fonts, imagery, and effects for the product—not from a blacklist or fashionable default. One memorable idea executed consistently beats many disconnected flourishes.

## Implement

- Preserve the current stack and component conventions.
- Build complete states: loading, empty, error, success, disabled, focus, hover, mobile, and long-content behavior where relevant.
- Use semantic HTML, correct labels, keyboard access, visible focus, sufficient contrast, and useful alt text.
- Centralize reusable tokens. Keep components composable without abstracting one-off visual details prematurely.
- Use motion to explain hierarchy or causality. Avoid scroll hijacking, gratuitous parallax, pointer-only interactions, and animation that blocks input.
- Use durable local assets when possible. Do not fabricate product data, customer proof, or completed backend behavior.

## Verify in the browser

Run formatting, lint, typecheck, tests, and production build. Inspect representative routes at mobile, tablet, and desktop widths. Exercise primary flows with keyboard and pointer. Check console/network errors, overflow, text wrapping, contrast, focus order, reduced motion, and slow-loading states.

Capture screenshots when visual review matters. Critique concept specificity, hierarchy, rhythm, typography, content fit, responsiveness, and interaction clarity. Revise the weakest dimension once before handoff.

Return changed paths, rendered result, verification evidence, and any mocked or unconnected behavior.

## Adaptive excellence

- Optimize for a memorable, usable frontend with one coherent concept.
- Use high freedom for typography, layout, imagery, color, and motion. Preserve brand fit, content truth, accessibility, responsiveness, and maintainability.
- Require one signature idea, strong screenshots at key viewports, and passing interaction/accessibility/build checks. Revise the weakest dimension once.
- Learn only from explicit critique, accepted screenshots, and project design decisions.
